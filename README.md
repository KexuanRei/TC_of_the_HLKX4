# 同步读取与重复更新修复

本包包含四个运行模块和一个回归测试文件，可覆盖到原 wps_mysql_sync 目录的相同位置。先备份同名文件，关闭同步服务和专用 Edge，再覆盖并启动 start_ui.bat。

## 修改内容

- 表A索引改为只读取主键列，仍按设置分批读到扫描终点，避开非主键隐藏列、宽表复制限制对索引的影响。
- 同步时，剪贴板返回的行数不足会拆小重读，不再直接假定缺少的行全是空白。
- 拆批写入时，每一小块分别重新复制、粘贴和回读校验，防止只把最后一块剪贴板内容写到整批起点。
- 即时同步不再把 Ctrl+C、Enter、方向键、地址框输入当作数据修改。删除、粘贴、剪切、撤销及实际输入继续触发监听。
- 即时同步也遵守每批行数限制；切换工作表、主键或范围时重建索引。
- 界面明确显示正在回读校验，避免将重复读取误认为重复粘贴。

## 本次文件对应的设置

原 config.json 的两张表均只扫描到 20000 行，未覆盖提供的本地文件。

| 设置 | D2 | A2 |
|---|---|---|
| 工作表 | 明细 | 临时 |
| 扫描范围 | A5:CB20230 | A5:CB48306 |
| 主键 | D | D |
| 数据起始行 | 5 | 5 |

这些终点依据本次提供的本地文件；后续新增行时应相应扩大扫描范围。用于 D2 副本时，应填写副本的链接、工作表和对应扫描范围，不能沿用 A2 的工作表名。

A2 本地文件的 F 列隐藏。新索引不会受 F 列影响；如果在线整行比较仍报告少列，需要在专用 Edge 中取消相关隐藏列或筛选后再试，不会以空白替代缺失列继续覆盖。

## 验证结果与限制

原有 145 项测试加 7 项新增回归测试，共 152 项通过。新增测试覆盖 48302 行索引、1000 行批次边界、复制截断、拆批粘贴、再次运行零更新、索引缓存及实际 JavaScript 监听事件。新测试在旧代码上可复现 6 项失败，在修复代码上全部通过。

已只读核对本地两表的范围、隐藏列和主键唯一性。在线 A2 可打开，但内置浏览器无法取得校验用剪贴板内容；未进行真实专用 Edge 的端到端写入测试，也未修改在线表或本地 Excel 文件。首批读取结束的具体历史错误仍需实际错误报告确认。

## 重启与验收

1. 关闭原同步服务以及该服务打开的专用 Edge，确保旧监听脚本被清除。
2. 重新运行原目录 start_ui.bat，刷新配置网页。
3. 核对链接、工作表及上述扫描范围，先执行“立即同步一次”。
4. A2 索引应依次显示 D5:D1004、D1005:D2004，持续读到 D48005:D48306。
5. 更新行校验成功后应继续下一批；再运行相同数据应更新 0 行。真实失败仍会停止并显示错误，不会跳过校验冒充成功。
6. 需要回退时，关闭服务后将原目录 backup_sync_fix_20261027_* 中的文件复制回相同位置，再重启。
